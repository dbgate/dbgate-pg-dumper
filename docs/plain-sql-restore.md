# Plain-SQL restore

`restoreSqlDump()` restores the sequential plain-SQL format emitted by
`dbgate-pg-dumper`. The implementation lives in this package because the writer
and reader must evolve together.

## Why it is not a `RestoreArchiveSource`

`RestoreArchiveSource` represents a structured, dependency-aware archive. Its
consumer reads archive metadata and the complete entry inventory before
preflight and execution, then opens data streams by ID. A sequential SQL file
has none of that information. Adapting it would require buffering or spooling
the file and inventing dependency metadata, so plain SQL has a separate
first-class restore API.

## Streaming behavior

The reader buffers at most one SQL statement. The default statement limit is
64 MiB and can be changed with `maxStatementBytes`. `COPY` payloads do not count
against that limit: they are split from the SQL stream and passed incrementally
to the existing native `COPY FROM STDIN` loader with backpressure.

The parser recognizes:

- single-quoted strings, including doubled quotes and conservative backslash
  escaping;
- quoted identifiers with doubled quotes;
- tagged and untagged dollar-quoted bodies;
- line comments and nested block comments;
- statement terminators only in normal SQL lexical state;
- the canonical `COPY schema.table (columns...) FROM STDIN` statements emitted
  by this package;
- `\.` COPY terminators with LF or CRLF line endings.

The API preserves transaction statements from the dump. On failure or
cancellation it attempts to roll back an active transaction before releasing
the caller-provided connection. It reports UTF-8 byte offsets, physical line
numbers, operation counts, COPY bytes, and rows through progress and typed
errors.

## Format detection

Use `isDumperSqlDump(sample)` on a leading file sample before selecting the
native reader. By default `restoreSqlDump()` also requires this marker:

```text
-- dbgate-pg-dumper PostgreSQL schema dump
```

This prevents arbitrary SQL files from being silently treated as compatible
package dumps.

## Intentional first-version limits

- Only UTF-8 plain-SQL dumps generated by a compatible `dbgate-pg-dumper`
  release are supported.
- `psql` meta-commands such as `\connect`, `\include`, `\copy`, variables, and
  conditionals are rejected.
- General SQL files and external `pg_dump` variants are not claimed to be
  compatible. Applications should retain their `psql` fallback for them.
- Structured-archive features such as dependency preflight, schema/role
  mappings, clean planning, conflict policies, and validation are not inferred
  from SQL text. Use the structured native restore engine when those features
  are required.
- The canonical text `COPY FROM STDIN` form emitted by this package is
  supported. CSV, binary COPY, program/file COPY, and arbitrary COPY option
  variants are outside this reader's scope.
